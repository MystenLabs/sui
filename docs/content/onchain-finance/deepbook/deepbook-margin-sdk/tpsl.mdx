The TPSL (Take Profit Stop Loss) SDK provides functions for managing conditional orders that automatically execute when certain price conditions are met. A conditional order pairs a trigger condition with a pending order. When the market price crosses the trigger price, the pending order executes automatically. Use take profit orders to lock in gains when price rises above a target, and stop loss orders to limit losses when price falls below a threshold.

## SDK setup

Import the DeepBook Margin SDK client and initialize it before calling any TPSL functions.

```tsx
import { DeepBookMarginClient } from '@mysten/deepbook-v3';
import { Transaction } from '@mysten/sui/transactions';

const traderClient = new DeepBookMarginClient({
  network: 'mainnet',
  // additional configuration
});
```

All TPSL functions return a callback that accepts a `Transaction` object. Pass the returned function directly to your transaction builder or call it with an existing `Transaction` instance.

## TPSL functions

The DeepBook Margin SDK provides the following functions for managing conditional orders.

### `addConditionalOrder`

Use `addConditionalOrder` to add a conditional order that executes when a price condition is met. The call returns a function that takes a `Transaction` object.

**Parameters**

- `marginManagerKey`: String that identifies the margin manager.
- `conditionalOrderId`: Number representing the unique ID for this conditional order.
- `triggerBelowPrice`: Boolean indicating whether to trigger when price falls below the trigger price.
- `triggerPrice`: Number representing the price at which to trigger the order.
- `pendingOrder`: Object containing the order details (either `PendingLimitOrderParams` or `PendingMarketOrderParams`).

### `cancelConditionalOrder`

Use `cancelConditionalOrder` to cancel a specific conditional order. The call returns a function that takes a `Transaction` object.

**Parameters**

- `marginManagerKey`: String that identifies the margin manager.
- `conditionalOrderId`: String representing the ID of the conditional order to cancel.

<ImportContent source="packages/deepbook-v3/src/transactions/marginTPSL.ts" mode="code" org="MystenLabs" repo="ts-sdks" fun="cancelConditionalOrder" signatureOnly />

### `cancelAllConditionalOrders`

Use `cancelAllConditionalOrders` to cancel all conditional orders for a margin manager. The call returns a function that takes a `Transaction` object.

**Parameters**

- `marginManagerKey`: String that identifies the margin manager.

<ImportContent source="packages/deepbook-v3/src/transactions/marginTPSL.ts" mode="code" org="MystenLabs" repo="ts-sdks" fun="cancelAllConditionalOrders" signatureOnly />

### `executeConditionalOrders`

Use `executeConditionalOrders` to execute conditional orders that have been triggered. This is a permissionless function that anyone can call. The call returns a function that takes a `Transaction` object.

**Parameters**

- `managerAddress`: String representing the address of the margin manager whose orders to execute.
- `poolKey`: String that identifies the DeepBook pool.
- `maxOrdersToExecute`: Number representing the maximum number of orders to execute in this call.

**Parameters**

### `newPendingLimitOrder`

Use `newPendingLimitOrder` to create a pending limit order for use in conditional orders. The call returns a function that takes a `Transaction` object.

**Parameters**

- `poolKey`: String that identifies the pool.
- `params`: `PendingLimitOrderParams` object containing:
  - `clientOrderId`: Number for client tracking.
  - `orderType`: Optional order type (default: `NO_RESTRICTION`).
  - `selfMatchingOption`: Optional self-matching option (default: `SELF_MATCHING_ALLOWED`).
  - `price`: Number representing the limit price.
  - `quantity`: Number representing the order quantity.
  - `isBid`: Boolean indicating if this is a buy order.
  - `payWithDeep`: Optional boolean for fee payment (default: `true`).
  - `expireTimestamp`: Optional expiration timestamp.

## Examples

### Set up a stop loss order

```tsx
// Example: Create a stop loss order that sells when price drops below 2.0
const setStopLoss = (tx: Transaction) => {
	const managerKey = 'MARGIN_MANAGER_1';
	traderClient.marginTPSL.addConditionalOrder({
		marginManagerKey: managerKey,
		conditionalOrderId: 1,
		triggerBelowPrice: true, // Trigger when price falls below
		triggerPrice: 2.0,
		pendingOrder: {
			clientOrderId: 100,
			quantity: 50,
			isBid: false, // Sell order
			payWithDeep: true,
		},
	})(tx);
};
```

### Set up a take profit order

```tsx
// Example: Create a take profit order that sells when price rises above 5.0
const setTakeProfit = (tx: Transaction) => {
	const managerKey = 'MARGIN_MANAGER_1';
	traderClient.marginTPSL.addConditionalOrder({
		marginManagerKey: managerKey,
		conditionalOrderId: 2,
		triggerBelowPrice: false, // Trigger when price rises above
		triggerPrice: 5.0,
		pendingOrder: {
			clientOrderId: 101,
			price: 5.0, // Limit order at 5.0
			quantity: 50,
			isBid: false, // Sell order
			payWithDeep: true,
		},
	})(tx);
};
```

### Execute triggered orders (keeper)

```tsx
// Example: Execute conditional orders as a keeper
const executeOrders = (tx: Transaction) => {
	const managerAddress = '0x...'; // Address of margin manager
	// Execute up to 10 triggered orders
	traderClient.marginTPSL.executeConditionalOrders(managerAddress, 'SUI_USDC', 10)(tx);
};
```

### Query and cancel orders

```tsx
// Example: Query all conditional order IDs, then cancel a specific order
const manageOrders = async () => {
  const tx = new Transaction();
  const managerKey = 'MARGIN_MANAGER_1';

  // Query existing conditional order IDs
  const orderIds = await traderClient.marginTPSL.conditionalOrderIds(managerKey);

  // Cancel a specific order by ID
  if (orderIds.length > 0) {
    traderClient.marginTPSL.cancelConditionalOrder({
      marginManagerKey: managerKey,
      conditionalOrderId: String(orderIds[0]),
    })(tx);
  }

  // Or cancel all conditional orders at once
  traderClient.marginTPSL.cancelAllConditionalOrders({
    marginManagerKey: managerKey,
  })(tx);
};
```

## How conditional orders work

A conditional order consists of two parts: a trigger condition and a pending order. When you call `addConditionalOrder`, the order is stored onchain and monitored against the current market price. When price crosses the trigger threshold, the pending order becomes eligible for execution.

Execution is permissionless. Any caller can invoke `executeConditionalOrders` for a given margin manager address. Keeper bots typically monitor trigger prices using `lowestTriggerAbovePrice` and `highestTriggerBelowPrice`, then call `executeConditionalOrders` when the current market price crosses those thresholds.

Set `triggerBelowPrice` to `true` for stop loss orders (trigger when price falls) and `false` for take profit orders (trigger when price rises). Pair the trigger condition with either a limit order (`newPendingLimitOrder`) for price-controlled execution or a market order (`newPendingMarketOrder`) for guaranteed fill at the prevailing price.
