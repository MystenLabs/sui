The DeepBookV3 TypeScript SDK abstracts away the transaction calls, allowing for direct interactions with the `DeepBook` package.

- [SDK repository](https://github.com/MystenLabs/ts-sdks/tree/main/packages/deepbook-v3)
- [NPM version](https://www.npmjs.com/package/@mysten/deepbook-v3)

## Install

To use the SDK in your projects, install the `@mysten/deepbook` package.

```sh npm2yarn
npm install @mysten/deepbook-v3
```

## Keys: Coin, Pool, and Manager {#keys}

Functions that require the input of a coin, pool, or a manager require the key of any such object as the parameter. The SDK manages a `key:value` relationship of this data in memory. Some default data comes with the SDK (as seen in `utils/constants.ts`). Coins are stored in a `CoinMap` and pools in a `PoolMap` in the config.

### Balance manager

Before placing any trade, you must supply a balance manager address to the client. The manager key points to an object defined by the `BalanceManager` interface in the client. [BalanceManager docs](/onchain-finance/deepbook/deepbookv3/contract-information/balance-manager). Initialize the balance manager with the client. If you don't create a balance manager, you can rely on the client to create one, but then the user must reinitialize the client.

Pass the manager under `balanceManagers` when you construct the client, keyed by a name you choose. The [market maker example](#deepbookclient) takes that map as its third argument.

If you do not have one yet, create and share a manager first, then reinitialize the client with its object ID:

### Coin

The SDK comes with four default coins on Testnet and five default coins on Mainnet.

**Default Testnet coins**

- DEEP
- SUI
- DBUSDC
- DBUSDT

**Default Mainnet coins**

- DEEP
- SUI
- USDC
- USDT
- WETH

You can also initialize the SDK with custom coins to interact with pools that are not supported by default. To do this, create a `CoinMap` object and pass it to the constructor of the client.

### Pool

Similar to coins, the SDK comes with default pools. Pass a `PoolMap` as the `pools` option, alongside `coins`, to override the defaults. The [market maker example](#deepbookclient) shows where those options go.

## Referral functions

The SDK provides functions for managing pool-specific referrals. Referrals allow users to earn a portion of trading fees from traders they refer.

### Pool referral functions

These functions live on the `deepBook` contract namespace (`client.deepbook.deepBook`) and manage referrals at the pool level.

:::info Multiplier constraints

The referral multiplier must be a multiple of 0.1 (such as 0.1, 0.2, or 0.3) and cannot exceed 10.0. [`pool::mint_referral`](https://github.com/MystenLabs/deepbookv3/blob/main/packages/deepbook/sources/pool.move) asserts both constraints against `referral_multiplier` and `referral_max_multiplier`, so a value that breaks either one aborts the transaction.

:::
