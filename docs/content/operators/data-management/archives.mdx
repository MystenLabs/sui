A Sui archive is a history of all transaction data on Sui. In some cases, peer nodes might not catch up with all transactions and effects through synchronization if they lag behind the current epoch by more than the latest few epochs. In such cases, instead of relying on synchronization, peer nodes can fall back to downloading the relevant information from an archive.

:::info
Starting with the 1.51 release, the default archive bucket for Mainnet switches to a requester-pays model. See the following section for a configuration example.
:::

`https://checkpoints.mainnet.sui.io` and `https://checkpoints.testnet.sui.io` retain only the most recent 30 days of checkpoints and are not suitable for full-retention backfill. For full checkpoint retention, use `gs://mysten-mainnet-checkpoints-use4` for Mainnet or `gs://mysten-testnet-checkpoints-use4` for Testnet with Requester Pays enabled. For standing up a new fullnode, always start it from a snapshot.

## Set up archival fallback {#set-up-archival-fallback}

To enable your node to fall back to an archive in case of lag, add the following to your `fullnode.yaml` file. The public HTTPS endpoints work for both Mainnet and Testnet and do not require AWS credentials:

<Tabs groupId="object-store">
<TabItem value="mainnet" label="Mainnet">

```yaml
state-archive-read-config:
  - ingestion-url: "https://checkpoints.mainnet.sui.io"
    # How many objects to read ahead when catching up
    concurrency: 5
```

</TabItem>
<TabItem value="testnet" label="Testnet">

```yaml
state-archive-read-config:
  - ingestion-url: "https://checkpoints.testnet.sui.io"
    # How many objects to read ahead when catching up
    concurrency: 5
```

</TabItem>
</Tabs>

:::info

The public HTTPS endpoints (`checkpoints.mainnet.sui.io` and `checkpoints.testnet.sui.io`) retain only the most recent 30 days of checkpoints. This is sufficient for archival fallback (catching up from short-term lag), but not for full-retention backfill. For indexer backfill or full checkpoint history, use the Requester Pays GCS or S3 buckets listed in the [archive source table](#archive-sources) below. Those buckets require cloud provider credentials.

:::

### Verify archival fallback

After adding the configuration and restarting your node, check the node logs for archive-related messages. You can also monitor the `checkpoints_synced_from_archive` Prometheus metric to confirm the node is fetching data from the archive:

```sh
$ curl -s http://localhost:9184/metrics | grep checkpoints_synced_from_archive
```

If the counter increases over time, the archival fallback is active.

### When to use each archive source {#archive-sources}

| Source | Retention | Credentials | Use case |
|--------|-----------|-------------|----------|
| `https://checkpoints.mainnet.sui.io` | 30 days | None | Mainnet fullnode archival fallback |
| `https://checkpoints.testnet.sui.io` | 30 days | None | Testnet fullnode archival fallback |
| `https://s3.us-west-2.amazonaws.com/mysten-mainnet-checkpoints` | Full history | AWS credentials | Mainnet full-retention backfill (S3 Requester Pays) |
| `gs://mysten-mainnet-checkpoints-use4` | Full history | GCS credentials | Mainnet full-retention backfill (GCS Requester Pays) |
| `gs://mysten-testnet-checkpoints-use4` | Full history | GCS credentials | Testnet full-retention backfill (GCS Requester Pays) |

For starting a new full node, always use a [snapshot](/operators/snapshots) rather than syncing from the archive.
