Nodes expose metrics on `localhost:9184/metrics` by default.

You can view the metrics in the metrics UI, or use a tool like `curl` to get the metrics in a format that is easy to parse.

```sh
$ curl -s http://localhost:9184/metrics | grep -E 'sui_validator|sui_fullnode'
```

## Key metrics

The following metrics are useful for monitoring node health:

| Metric | Description |
|---|---|
| `uptime` | Time since the node process started |
| `highest_synced_checkpoint` | The latest checkpoint the node has synced |
| `last_executed_checkpoint` | The latest checkpoint the node has executed |
| `sui_fullnode_highest_known_checkpoint` | The highest checkpoint known to the network (compare against `highest_synced_checkpoint` to detect sync lag) |
| `total_transactions` | Total number of transactions processed |

## Production monitoring

For production monitoring, use [Prometheus](https://prometheus.io/) to scrape metrics and [Grafana](https://grafana.com/) to visualize them.

### Prometheus configuration

Add a scrape target for your Sui node in your `prometheus.yml`:

```yaml
scrape_configs:
  - job_name: 'sui-node'
    static_configs:
      - targets: ['HOSTNAME:9184']
```

Replace `HOSTNAME` with your node's hostname or IP address. The default metrics port is **9184**.

### Grafana setup

1. Add Prometheus as a data source in Grafana (Settings > Data Sources > Add data source > Prometheus).
2. Set the Prometheus URL to your Prometheus instance (for example, `http://localhost:9090`).
3. Create a dashboard with panels for key metrics like `highest_synced_checkpoint`, `last_executed_checkpoint`, and `total_transactions`.

### Alerting

Set up alerts for the following conditions:

- **Sync lag:** Alert when `highest_synced_checkpoint` falls more than 100 checkpoints behind `sui_fullnode_highest_known_checkpoint`.
- **Node down:** Alert when the Prometheus target is unreachable for more than 5 minutes.
- **High resource usage:** Alert on CPU or memory usage thresholds specific to your infrastructure.
