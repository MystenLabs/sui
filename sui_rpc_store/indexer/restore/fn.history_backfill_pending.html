Whether the history cohort is still backfilling below a restore’s target T, so checkpoint-pinned reads must wait.

Two restores leave it behind T:

  • When a prefix of the chain has been pruned (L > 0), the restore loads the history floors’ (object_version_by_checkpoint and package_versions) rows at T and the history backfill then fills in [L, T]. Until a floor pipeline has committed T, a checkpoint-pinned read at a checkpoint the backfill has already passed can still be wrong: an object or package version whose first change in the window comes later than the backfill has reached resolves to its floor row at T, as if nothing had changed since. Lowering the read’s upper bound does not help, because any checkpoint in [L - 1, T] can be affected (a read at L - 1 is served, since the state at its end is the input state of L). A floor pipeline that was never restored has no floor rows and does not count; a floor restore that has not completed counts as pending.
  • When nothing has been pruned (L == 0), only the live cohort is restored (RestoreLayer::live_only) and the history cohort backfills from genesis with no restore rows of its own. Its reads are exact, but the indexed tip is the backfill’s height, so a read pinned to that tip answers with state far behind the live cohort’s T. A history pipeline that has committed a checkpoint below the live cohort’s restore target therefore counts as pending, as does a live-cohort restore that has not completed. History pipelines without a watermark do not count: until every registered one has committed, the indexed tip is unset and checkpoint-pinned reads are refused regardless.

Between the restore’s finalize, which stamps the floors’ watermarks at T, and seed_history_cohort, which rewinds them to L - 1, this returns false although nothing in [L, T] has been backfilled. That state is never served: the embedded bootstrap runs both before it starts serving, and repairs a crash between them with the seed (history_seed_pending). In it, the other history pipelines have no watermark, so the indexed tip is unset and checkpoint-pinned reads are refused regardless.
