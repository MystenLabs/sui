Singleton row recording that the startup build of super::packages_by_checkpoint from super::package_versions has completed. The row’s presence is the record; its value is empty.

The build writes this row in the same batch as its last chunk, so a crash mid-build leaves no row and the next open finishes the build. RpcStoreSchema::open skips the build while the row exists: after the build, every writer of a package_versions row with a known publish checkpoint writes its packages_by_checkpoint row in the same batch, so rescanning would find nothing to write.

The row lives in its own CF, rather than under a made-up pipeline key in the framework’s __restore or __watermark CFs, because code walks every __watermark entry (the pruner’s epoch floor) and would read such an entry as a pipeline.
